## Contexte (2026-10-03)

Terminal intégré (`SPECS-P5-UI-PARITE.md` §5). **Téléchargement autorisé par l'utilisateur** (« telechargement autorisé », 2026-10-03), après que l'agent eut dit que `node-pty` et `xterm.js` exigeaient un téléchargement : `node-pty@1.1.0` (15,5 Mo téléchargés, 64 Mo décompressés), `@xterm/xterm@6.0.0` (5,9 Mo), `@xterm/addon-fit@0.11.0` (20 Ko), depuis `registry.npmjs.org` ; `node-addon-api@7.1.1` en dépendance de `node-pty`. Commande : `pnpm --filter @jarod/desktop add --save-exact --prefer-offline --ignore-scripts node-pty@1.1.0 @xterm/xterm@6.0.0 @xterm/addon-fit@0.11.0` ; lockfile d'avant : `.work/lock-before-b24.yaml` ; variantes `openvino`/`onnxruntime`/`supports-color` de `node_modules/.pnpm` comparées avant/après : IDENTIQUES (`.work/pnpm-variants-*-b24.txt`).

`node-pty` déclare `install` (`node scripts/prebuild.js || node-gyp rebuild`) et `postinstall` : **aucun n'est exécuté** (`--ignore-scripts`, et `node-pty` n'est pas dans `allowBuilds`). Il est inutile ici : le paquet embarque ses binaires N-API précompilés (`prebuilds/win32-x64`, `win32-arm64`, `darwin-x64`, `darwin-arm64` ; ConPTY sous Windows), qui se chargent sous Node et sous Electron 44 sans recompilation. Vérifié : lancement d'un `cmd.exe` par ConPTY sous Node, puis un shell réel dans l'application Electron (`ui.e2e.test.ts` : l'écran Terminal affiche l'invite). Pas de prébuilt Linux dans le paquet : sur Linux il faudrait `node-gyp rebuild` (chaîne de compilation), à décider avant une distribution Linux.
